# 3D without outside services

Never ask for Sketchfab, Fab or any other 3D site's key, token or link. Everything is drawn in code (Canvas 2D, SVG, Three.js, shaders), or, only if the user wants it and has it, in their local Blender. Three.js (MIT) is already in the library's `node_modules`.

## Ask once, in the one round of questions

Only when the film needs 3D objects or characters: "Stylised, code-built 3D (fast, no rigging) — or a real model with organic bending joints (needs Blender on your machine)?" Default to stylised.

All three modes are ready in the kit (`get_kit`): `three/procedural_rig.js` (`SVGExtrudeHero`, `HierarchicalRigidJoints`, `SkeletonlessShaderRig`), and for Blender `blender/character_blockout.py`, `blender/character_check.py`, `blender/blender_autoweight.py`, `blender/mesh_export.py`.

## Mode A — SVG extruded to 3D (no skinning)

Logos, products, glass/metal blocks, isometric dioramas, architecture. Draw the outline as an SVG path → `SVGLoader` → `ExtrudeGeometry` (bevel on), or `LatheGeometry` for turned objects.

## Mode B — characters without a skeleton (no weights to break)

- **Shader pose:** one shared vertex-shader function moves vertices by their position: breathing (scale along y with `sin(t)`), walk sway (offset x by `sin(t·k)·smoothstep(hip, foot, y)`), bend (rotate around a pivot by an angle weighted by height). Blinks on a separate eyelid mesh; fur with shell layers.
- **Rigid joints:** each limb a separate mesh inside its own `Object3D`, pivot at the joint; animate rotations only. Walk cycle = phase-offset `sin` per limb. No `SkinnedMesh`, so no weight table to get wrong.

Both are pure functions of `t`, so they stay frame-deterministic.

## Mode C — real deforming model (optional)

Only if the user chose it **and** `python kit/blender/mesh_export.py --check` finds Blender. Otherwise say so and fall back to Mode B.

**Characters: follow guide "blender"** (spec → `blender/character_blockout.py` proxy → real model → rig → `blender/character_check.py` PASS + its sheet looked at). The snippet below only parents an existing model to an existing armature.

```python
# blender -b -P rig.py -- in.blend out.glb
import bpy, sys
src, dst = sys.argv[sys.argv.index("--") + 1:]
bpy.ops.wm.open_mainfile(filepath=src)
arm = next(o for o in bpy.data.objects if o.type == "ARMATURE")
for mesh in [o for o in bpy.data.objects if o.type == "MESH"]:
    bpy.ops.object.select_all(action="DESELECT")
    mesh.select_set(True); arm.select_set(True)
    bpy.context.view_layer.objects.active = arm
    bpy.ops.object.parent_set(type="ARMATURE_AUTO")   # automatic weights from bones
bpy.ops.export_scene.gltf(filepath=dst, export_format="GLB")
```

If a limb pulls the wrong part (a leg dragging the other leg or the trousers), give the user this short checklist instead of trying again blind:
1. Select the mesh → Weight Paint mode.
2. Pick the bone that misbehaves; paint its weight off the wrong area (Subtract brush), or Weights → Assign Automatic from Bones on that bone only.
3. Object Data → Vertex Groups: delete empty or misnamed groups.
4. Save and tell you; you export again.

## Blender as a modelling tool (props, any mode)

When the film needs props more complex than plates and boxes (vehicles, instruments, machines) and the user has Blender, model them with a bpy script and export geometry only: `python kit/blender/mesh_export.py --check` finds Blender (PATH, `STYLIST_BLENDER`, Program Files, Steam libraries), `--run model.py out.json` runs the script headless with a clean environment (a Python/conda on PATH can hang Blender's own Python on Windows). The film's renderer still draws the parts, so the style's look is unchanged.
- One object per real part (so it can come apart), tagged with `part(obj, name, colour)`; coordinates come out Y-up in centimetres.
- Model beside a reference picture, then check a 12-angle turnaround closed and apart before animating. More in guide "blender".
